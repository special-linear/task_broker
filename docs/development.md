# Development and verification

Use Node 24+, the committed npm lockfile, Python 3.10+, and the pinned Wrangler version. No global Wrangler installation is required. `npm ci`, `npm run db:local`, then `npm run dev` starts the persisted local Worker. Windows PowerShell users can substitute `npm.cmd` for `npm`.

Run `npm run typecheck`, `npm test`, `npm run test:python`, `npm run build`, and `npm run api:generate -- --check`. Worker tests run against Cloudflare's workerd/D1 integration, including transactional rollback, concurrent claims, revision races and signature validation. They do not use an in-memory broker substitute.

Before browser tests, install Chromium and Firefox using `PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright npx playwright install chromium firefox` (PowerShell: set `$env:PLAYWRIGHT_BROWSERS_PATH='.cache/ms-playwright'` first). Start the local Worker after rebuilding browser assets, then run `npm run test:browser`. Wrangler's development asset manifest may require a restart when Vite emits newly named assets. This does not affect deployed assets.

For staging, copy `wrangler.example.jsonc` to ignored `wrangler.staging.local.jsonc` and fill in the real deployment values there. Staging deployment, validation and verification tools select this file automatically; `WRANGLER_CONFIG` overrides it. Use `node scripts/wrangler.mjs` in place of direct Wrangler commands when selecting private deployment configuration. Local development still uses the generic root configuration. Run Wrangler authentication in the actual execution environment. Keep Cloudflare API credentials in local environment variables or Wrangler's credential store. Establish an administrator session with `cloudflared access login --quiet <admin URL>`; optionally set `CF_ACCESS_TOKEN_FILE` to a private session file. The browser session and all verification keys belong in ignored `artifacts/private/`.

`node scripts/remote-check.mjs` exercises the real deployed broker and D1. `node scripts/performance.mjs` stages and applies 10,000 tasks, retries committed chunks, verifies a complete export, and measures steady and burst traffic. This workload exceeds a Free daily write allowance; use a smaller `PERF_TASKS` value or split work across days on a confirmed Free account. Run `node scripts/browser-journey.mjs` for the protected browser and downloaded Python journey. Remote tests mutate disposable fixtures and retain their history. `node scripts/cloudflare-control.mjs rollback-test` injects a task-scoped D1 failure and removes its trigger in a finally block; it needs a Cloudflare API token or the local Wrangler credential store. `plans` and `metrics` read provider query plans and CPU analytics. `PERF_RUN_LABEL=optimized-1000 PERF_TASKS=1000` preserves a separate performance artifact.

`node scripts/backup-verification.mjs` exports the source under maintenance and reopens it in a finally block. Its SQL contains credentials and remains private. Build a local bundle using `wrangler deploy --dry-run --env local --outdir artifacts/private/restore-worker`, then `node scripts/restore-verification.mjs` restores into a new isolated local D1 directory, rotates the epoch, quarantines restored keys, and tests fresh work. `node scripts/idle-verification.mjs` requires the performance fixture and runs without application requests for 30 minutes; avoid other staging requests during the observation.

New verification reports remain in ignored `artifacts/private/verification/`. Review and sanitize selected reports into `docs/evidence/` before sharing.

Run `npm run check:privacy -- --history` and `npm run test:publication` before publication. Generate the release with `npm run release`. Check the ZIP hashes and inspect its allowlisted contents. It contains account-independent deployment configuration, source, reproducible browser assets, Python, OpenAPI, manuals, license texts, and public verification evidence. Private SQL backups, session files, keys, node_modules and local databases are excluded.
